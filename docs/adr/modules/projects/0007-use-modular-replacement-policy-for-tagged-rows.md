# Use a modular replacement policy for tagged rows

The initial replacement rule should match the existing portal while allowing the parser to read multiple bracket tags from `Remark`: Bidcon rows on the same tree level may replace each other when they share at least one `Remark` tag value, such as `{minTagg}`, and the original row quantity is applied to the replacement row. The initial policy does not require the same technical row or item type beyond same tree level and shared tag; Bidcon tagging is the business-controlled boundary. For MVP, a tagged candidate also needs enough data for safe rendering, such as quantity and unit price on both original and replacement rows. Candidates that fail this data check are not shown as selectable in the first UI, but should be diagnosable. For compatibility, every bracket tag is initially treated as a replacement tag, but the syntax should be isolated in a parser so future namespaced forms such as `{replace:kyla}` can be introduced without changing the broader snapshot model.
